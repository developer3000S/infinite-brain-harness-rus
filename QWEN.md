# Корень репозиториев, Multi-Brain Workspace (ориентация для Qwen Code)

Это корень репозиториев: общий родительский уровень топологии Infinite Brain и папка, которую вы открываете в Qwen Code. Его задача — направлять вашу работу в нужный мозг и синхронизировать каждый мозг. Ориентируйтесь из этого файла. Файлы `CLAUDE.md` и `AGENTS.md` — наследие предыдущих версий; этот файл является основной ориентацией для Qwen Code.

Есть два способа запуска этого корня, и они дополняют друг друга. Основная форма — мульти-мозговой workspace: несколько мозгов, смонтированных в `brains/`, с которыми вы работаете каждый день. Вторичная форма — корень реестра для операции, работающей со многими репозиториями. Большинство людей хотят workspace.

## Workspace: мозги, смонтированные в `brains/`

`brains/` содержит мозги, с которыми вы работаете, каждый — независимый git-репозиторий, клонированный через `/start`:

- общий мозг (мозг компании или отдела, который перерос в собственный репозиторий): основная рабочая поверхность, канон, на который полагаются все;
- ваш индивидуальный мозг (`individual-<имя>/`): ваш личный слой для набросков и исследований с меньшими ограничениями.

Если `brains/` пуст, это новая машина: выполните `/start`, и он клонирует ваши мозги.

### Правило маршрутизации (какой мозг получает работу)

1. **По умолчанию используйте общий мозг** для реальной, общей работы или чтения канона. Читайте его канон; никогда не копируйте его в другой мозг, ссылайтесь на него по пути.
2. **Индивидуальный мозг для всего нового, неопределённого или разрушительного.** Если работа может быть ошибочной или может сломать то, на что полагаются другие, она начинается в вашем индивидуальном мозге. Там дешево ошибаться.
3. **Проверенная индивидуальная работа продвигается наверх, никогда не редактируется в общем мозге напрямую.** `/sync` направляет любые основные изменения в общем мозге в ветку `proposal/<slug>-<topic>` для ревью.

`.qwen/CAPABILITIES.md` (регенерируемый через `/sync`) перечисляет, что содержит каждый смонтированный мозг: его инструменты, рабочие процессы, агентов, навыки и знания, с однострочным описанием, когда использовать, чтобы вы могли направлять работу в правильный мозг конкретно, а не гадать.

### Команды

- `/start`: настраивает или пробуждает эту машину. Устанавливает доступ к git (по умолчанию GitHub), создаёт или клонирует каждый мозг в `brains/` (на совершенно новом запуске он создаёт приватные удалённые репозитории и перенаправляет origin стартового клона на собственный репозиторий человека), проверяет и регистрирует каждый мозг, затем выполняет `/sync`.
- `/sync`: сохраняет вашу работу и получает последние обновления. Пушит ваш индивидуальный мозг свободно; пушит содержимое общего мозга (выходные данные, сессии) в общую ветку; направляет основные изменения общего мозга в ветку `proposal/<slug>-<topic>` для ревью; тянет последние обновления; обновляет копируемый слой команд и индекс возможностей из каждого мозга.
- `/save`: коммитит вашу работу в каждом мозге с вашим именем, без пуша.
- `/promote-to-department`: упаковывает что-то из вашего индивидуального мозга для ревью.
- `/workspace-help`: объясняет workspace простыми словами.

### Как работают собственные команды мозга здесь

Qwen Code загружает только `.qwen/` этого корня, никогда дочернего репозитория. Поэтому `/start` и `/sync` копируют `.qwen/{commands,skills,agents,rules}` каждого смонтированного мозга в `.qwen/` этого корня, чтобы собственные инструменты мозга стали слеш-командами здесь. Они загружаются после перезапуска Qwen Code. Скопированная команда выполняется против исходного мозга, поэтому сначала она переходит в папку этого мозга (см. `.qwen/COPIED-FROM.md`). Собственные команды workspace выше никогда не перезаписываются.

## Корень реестра (вторичный: запуск многих репозиториев)

Когда операция работает с более чем горсткой мозгов, смонтированных в `brains/`, плюс репозитории приложений (продуктовые и клиентские кодовые базы), она также использует этот корень как реестр. Дочерние репозитории находятся в `internal/` (репозитории, которыми владеет эта операция) и `external/` (клиентские или совместно управляемые репозитории, сгруппированные в `external/<группа>/`), каждый — независимый git-репозиторий, который harness игнорирует и знает только через запись в `repo-registry/`. `repo_kind` может быть `brain`, `app` или `mixed`; мозг также имеет `brain_tier` уровня `individual`, `department` или `company`. Чтобы зарегистрировать репозиторий, следуйте `ADD-A-BRAIN.md` или выполните команду `register-repo`. Репозиторий приложения — обычный сосед без онтологии мозга и без уровня.

Реестр — полная карта того, что находится в этом корне; `brains/` — под��ножество, с которым вы активно работаете. Мозг, смонтированный в `brains/`, также может иметь запись в реестре, когда операция хочет включить его в полную инвентаризацию.

## Что этот корень никогда не содержит

Никакого собственного содержимого мозга: никаких знаний, доктрин или сущностей, созданных здесь. Мозги в `brains/` и дочерние репозитории в `internal/`/`external/` — независимые git-репозитории с собственными удалёнными репозиториями и историей; этот корень игнорирует их содержимое в git и не предоставляет им резервного копирования. Каждый мозг имеет собственную историю резервного копирования через свои удалённые репозитории. Копируемый слой команд и индекс возможностей генерируются, игнорируются git и регенерируются через `/sync`; они доступны только для чтения ниже по потоку и никогда не являются вторым источником истины. Никаких секретных значений здесь нет.
