# /start: настройка (или пробуждение) этого workspace

Запустите это первым на новой машине и снова каждый день. Он устанавливает доступ к git, клонирует ваши мозги в `brains/`, проверяет и регистрирует их, и синхронизирует. Работайте автономно и проверяйте каждый шаг перед следующим; останавливайтесь только для входа в систему, который человек должен кликнуть, и точно говорите ему, что кликнуть. Отчитывайтесь о каждом шаге одной простой строкой. Установите `GIT_TERMINAL_PROMPT=0`, чтобы git быстро завершался с ошибкой вместо зависания на запросе учётных данных.

## Шаг 1: Доступ к git (GitHub по умолчанию)

- Убедитесь, что git установлен и `user.name` и `user.email` заданы. Если нет, установите их (спросите один раз).
- Убедитесь, что git-хост доступен и аутентифицирован. GitHub — бэкенд по умолчанию: проверьте `gh auth status`, или SSH-ключ, или менеджер учётных данных. Если `gh` не установлен, направьте человека на https://cli.github.com/ (один установщик на ОС), затем попросите его запустить `gh auth login` и выбрать HTTPS плюс вход через браузер; SSH-ключ по документации GitHub работает одинаково хорошо. Если последующее клонирование завершится с ошибкой аутентификации, это означает, что этот шаг не завершён: исправьте аутентификацию и повторите. Никогда не сохраняйте токен в репозитории. Альтернативный бэкенд (самостоятельно размещённый или закрытый git-хост) меняет только URL удалённого репозитория и его вход в систему; остальная часть этой команды неизменна.

## Шаг 2: Узнайте, какие мозги монтировать

- Прочитайте `.claude/brains.conf`: одна строка `folder = git-remote-url` на строку, строки, начинающиеся с `#`, игнорируются.
- Если он существует, перейдите к Шагу 3. Если он отсутствует или пуст, спросите человека, в каком случае он находится:
  - **У него уже есть мозги** (член команды присоединяется к существующему развёртыванию): спросите два удалённых репозитория, их **общий мозг** (мозг компании или отдела) и их **индивидуальный мозг** (названный `individual-<их-имя>`), и запишите файл.
  - **Он начинает с нуля** (одиночный ученик, нет существующих репозиториев): создайте оба мозга сейчас, согласно Шагу 2a. Каждый удалённый репозиторий, записанный в `brains.conf`, должен быть репозиторием, в который человек может пушить; никогда не записывайте туда URL публичного стартера.
  `.claude/brains.conf` локальный и игнорируется git; он не содержит секретов, только URL репозиториев.

### Шаг 2a: Начинаем с нуля (одиночный путь)

1. **Мозг компании из публичного стартера.** Клонируйте стартер, затем немедленно перенаправьте origin на новый приватный репозиторий, которым владеет человек: в публичный стартер нельзя пушить, поэтому пока origin не перенаправлен, мозг не имеет резервной копии, и каждый последующий `/sync` push завершится ошибкой.

   ```bash
   git clone https://github.com/starmynd-org/infinite-brain-os.git brains/<name>-brain
   gh repo create <name>-brain --private        # или создайте пустой приватный репозиторий в веб-интерфейсе GitHub
   git -C brains/<name>-brain remote set-url origin https://github.com/<user>/<name>-brain.git
   GIT_TERMINAL_PROMPT=0 git -C brains/<name>-brain push -u origin main
   ```

2. **Индивидуальный мозг.** Новорождённый индивидуальный мозг — это пустой приватный репозиторий, не более того; первый `/save` плюс `/sync` запишут его начальный коммит. Когда git говорит "You appear to have cloned an empty repository", это ожидаемое состояние, не ошибка.

   ```bash
   gh repo create individual-<name> --private
   git clone https://github.com/<user>/individual-<name>.git brains/individual-<name>
   ```

3. Запишите обе строки в `.claude/brains.conf` с собственными URL удалённых репозиториев человека.

## Шаг 3: Клонирование или обновление каждого мозга

```bash
mkdir -p brains
# для каждой строки "folder = remote" в .claude/brains.conf:
#   если brains/<folder>/.git отсутствует:  git clone <remote> brains/<folder>
#   иначе: оставьте его; /sync обновит его.
```

При ошибке аутентификации при клонировании это проблема доступа к git из Шага 1, не реальная ошибка: исправьте аутентификацию и повторите.

## Шаг 4: Проверка каждого мозга, который может проверяться

Для каждого мозга в `brains/`, который содержит `_system/validate.sh` (любой мозг, построенный из стартера):

```bash
(cd brains/<folder> && bash _system/validate.sh)
```

Свежий клон завершается с кодом 0 с сообщением "All checks passed" (небольшой набор известных предупреждений на предоставленном примере содержимого является частью базовой линии). Ненулевой код завершения на свежем клоне означает, что клон или окружение сломаны; остановитесь и сообщите об этом, прежде чем делать что-либо ещё.

## Шаг 5: Регистрация каждого мозга

Каждый смонтированный мозг получает одну запись в `repo-registry/`, чтобы любой агент, ориентирующийся в этом корне, знал, что это такое. Для каждого мозга, который ещё не зарегистрирован: скопируйте `repo-registry/_template.md` в `repo-registry/<folder>.md`, заполните каждое поле (`repo_kind: brain`; `brain_tier: company` для общего мозга, `individual` для личного; `remote:` — собственный URL человека из `brains.conf`), и закоммитьте запись в этом корне. `ADD-A-BRAIN.md` документирует поля. Примечание для одиночных учеников: этот корень был клонирован из публичного harness, поэтому коммиты реестра остаются локальными, пока вы не дадите корню собственный приватный удалённый репозиторий так же, как в Шаге 2a; локальный режим нормален для начала.

## Шаг 6: Синхронизация

Запустите `/sync`, чтобы сохранить всё, что уже здесь, получить последние обновления и обновить копируемый слой команд и индекс возможностей.

## Шаг 7: Перезапуск и отчёт

1. Дайте короткий контрольный список: доступ к git работает, какие мозги присутствуют и на каком коммите, что каждый проверяющий мозг прошёл проверку, и что у каждого мозга есть запись в реестре.
2. Скажите человеку **перезапустить Claude Code сейчас**. Собственные слеш-команды мозгов, которые `/sync` только что скопировал, загружаются только при перезапуске; до этого они не появляются, что в противном случае выглядит как неудачная установка. После перезапуска `/workspace-help` объясняет остальное.
